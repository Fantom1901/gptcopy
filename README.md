# 🚀 gptcopy

**gptcopy** — консольная утилита на **Rust** для быстрой подготовки контекста проекта для LLM: ChatGPT, Claude, DeepSeek и других моделей.

Утилита сканирует проект, формирует его структуру и содержимое текстовых файлов в единый контекст, после чего автоматически копирует результат в системный буфер обмена.

Основная задача `gptcopy` — быстро передать LLM только действительно полезную часть проекта без ручного копирования десятков файлов.

---

## ✨ Возможности

- ⚡ **Rust CLI** — нативный исполняемый бинарник на Rust.
- 📂 **Сканирование проекта** — автоматически собирает дерево каталогов и содержимое текстовых файлов.
- 🚫 **Встроенный ignore-list** — пропускает зависимости, служебные каталоги, build-артефакты, кэши и lock-файлы.
- 🧩 **Поддержка `.gitignore`** — дополнительно учитывает правила `.gitignore` в корне переданного проекта.
- 🌿 **Git-режим** — позволяет собрать только изменённые, новые и untracked-файлы.
- 🗜️ **Минификация** — удаляет пустые строки для уменьшения размера контекста.
- 🏷️ **XML-режим** — формирует структурированный XML-контекст.
- 🎯 **Фильтр расширений** — позволяет ограничить сбор определёнными расширениями.
- 🔐 **Поиск потенциальных секретов** — предупреждает о возможных API-ключах, приватных ключах и токенах.
- 📝 **Определение текстовых файлов** — бинарные файлы автоматически пропускаются.
- 📋 **Автоматический буфер обмена** — поддерживаются `kitten`, `wl-copy` и `xclip`.
- ⌨️ **Автодополнение терминала** — генерация completion-скриптов для Bash, Zsh, Fish и других shell, поддерживаемых `clap_complete`.
- 📊 **Статистика** — после выполнения показывает количество файлов, размер результата и приблизительное количество токенов.
- 📁 **Несколько целей** — можно передать несколько файлов и директорий за один запуск.

---

# 🦀 Реализация

Проект реализован на **Rust** с использованием:

- `clap` — разбор аргументов и подкоманд CLI;
- `clap_complete` — генерация shell completions.

Основная логика выполняется непосредственно CLI-бинарником без отдельного runtime.

Общий pipeline:

```text
CLI arguments / subcommand
        │
        ├── completions
        │      └── shell completion generation
        │
        └── обычный запуск
               │
               ▼
        Определение targets
               │
               ▼
        Загрузка .gitignore
               │
               ▼
        PROJECT STRUCTURE
               │
               ├── Git status
               └── Рекурсивное дерево
               │
               ▼
        Сбор файлов
               │
               ├── Ignore list
               ├── .gitignore
               ├── Text-file detection
               └── Extension filter
               │
               ▼
        Обработка файлов
               │
               ├── Secret scan
               ├── Minify
               └── XML / обычный формат
               │
               ▼
        Готовый контекст
               │
               ├── Clipboard
               │     ├── kitten
               │     ├── wl-copy
               │     └── xclip
               │
               └── Console fallback
               │
               ▼
        Итоговая статистика
```

# 🛠 Установка

## Установка через GitHub Releases

Для установки используется официальный installer:

```bash
curl -sSL https://raw.githubusercontent.com/Fantom1901/gptcopy/main/install.sh | bash
```

Инсталлятор:

1. создаёт `$HOME/.local/bin`;
2. создаёт рабочую директорию `$HOME/scripts/gptcopy`;
3. получает последний GitHub Release;
4. скачивает актуальный бинарник;
5. создаёт ссылку `~/.local/bin/gptcopy`;
6. при необходимости добавляет `~/.local/bin` в `PATH`.

Поддерживаются:

- **Bash**
- **Zsh**
- **Fish**

Для Fish автоматически добавляется:

```fish
fish_add_path ~/.local/bin
```

Для Bash/Zsh добавляется соответствующий `PATH`.

После установки перезапустите терминал либо загрузите shell-конфигурацию командой, которую покажет installer.

---

## Удаление

Установку можно удалить через тот же installer:

```bash
curl -sSL https://raw.githubusercontent.com/Fantom1901/gptcopy/main/install.sh | bash -s -- --uninstall
```

Инсталлятор удаляет бинарник `gptcopy` и связанную с ним настройку `PATH`.

# 🚀 Использование

Общий синтаксис:

```text
gptcopy [пути] [флаги]
gptcopy <команда>
```

Если путь не указан, используется текущий каталог:

```bash
gptcopy
```

То же самое:

```bash
gptcopy .
```

---

## 📁 Собрать весь проект

```bash
gptcopy .
```

Утилита:

- строит дерево проекта;
- находит текстовые файлы;
- исключает игнорируемые элементы;
- добавляет содержимое файлов;
- копирует результат в буфер обмена.

---

## 📂 Собрать конкретную директорию

```bash
gptcopy src/
```

Можно указывать несколько целей:

```bash
gptcopy src/ tests/ Cargo.toml
```

Поддерживаются как директории, так и отдельные файлы.

---

## 🗜️ Минификация

Флаг:

```bash
-m
```

или:

```bash
--minify
```

Удаляет пустые строки из содержимого файлов.

Пример:

```bash
gptcopy src/ -m
```

Это полезно, когда необходимо уменьшить размер контекста и количество токенов.

---

## 🌿 Только изменённые файлы Git

Флаг:

```bash
-c
```

или:

```bash
--changed
```

Использует Git и получает список файлов через:

```bash
git ls-files -m -o --exclude-standard
```

В результат попадают:

- изменённые tracked-файлы;
- новые untracked-файлы;
- файлы, которые не исключены стандартными Git ignore-правилами.

Структура проекта в этом режиме формируется через:

```bash
git status -s
```

Пример:

```bash
gptcopy -c
```

Особенно удобно при работе над уже существующим проектом:

```text
Проект
 ├── backend/
 ├── frontend/
 ├── docs/
 └── ...
       ↓
   gptcopy -c
       ↓
Только актуальные изменения
```

Если текущий каталог не является Git-репозиторием, структура проекта содержит сообщение `Git не инициализирован`.

---

## 🏷️ XML-режим

Флаг:

```bash
-x
```

или:

```bash
--xml
```

Формирует результат в XML-структуре вместо обычного Markdown-подобного формата.

Пример:

```bash
gptcopy src/ -x
```

Результат имеет структуру:

```xml
<project_structure>
...
</project_structure>

<source_code>
<file path="src/main.rs">
...
</file>

<file path="src/lib.rs">
...
</file>
</source_code>
```

XML-режим удобен для моделей, которым требуется явно структурированный контекст.

---

## 🎯 Фильтр по расширениям

Флаг:

```bash
-e
```

или:

```bash
--ext
```

Позволяет указать список расширений через запятую.

Например:

```bash
gptcopy . -e rs,toml
```

Будут обработаны только файлы с расширениями:

```text
*.rs
*.toml
```

Можно комбинировать фильтр с другими режимами:

```bash
gptcopy . -c -m -e rs,toml
```

### Важно

Расширения передаются **без точки**:

```bash
gptcopy . --ext rs,toml
```

Запись:

```bash
gptcopy . --ext .rs,.toml
```

не соответствует текущей реализации фильтра расширений.

Сравнение выполняется без учёта регистра.

# ⌨️ Автодополнение терминала

`gptcopy` использует `clap_complete` и предоставляет отдельную подкоманду:

```text
gptcopy completions <shell>
```

Поддерживаемый shell определяется самим `clap_complete`.

Посмотреть доступные варианты можно через:

```bash
gptcopy completions --help
```

---

## Bash

Сгенерировать completion:

```bash
gptcopy completions bash > ~/.local/share/bash-completion/completions/gptcopy
```

После этого перезапустите shell или загрузите completion-конфигурацию Bash.

---

## Zsh

Сгенерировать completion:

```bash
gptcopy completions zsh > ~/.zfunc/_gptcopy
```

Убедитесь, что `~/.zfunc` находится в `fpath`, например:

```zsh
fpath=(~/.zfunc $fpath)
autoload -Uz compinit
compinit
```

---

## Fish

Сгенерировать completion:

```fish
gptcopy completions fish > ~/.config/fish/completions/gptcopy.fish
```

После этого Fish автоматически подхватит completion-файл.

---

## Другие shell

`clap_complete` также поддерживает другие shell, если они доступны в используемой версии библиотеки.

Общий принцип:

```bash
gptcopy completions <shell>
```

Например:

```bash
gptcopy completions powershell
```

Команда печатает готовый completion-скрипт в `stdout`, поэтому его можно перенаправить в соответствующий файл конфигурации shell.

## 📄 Поддержка `.gitignore`

Помимо встроенного списка, `gptcopy` пытается прочитать:

```text
.gitignore
```

в корне переданного проекта.

Строки `.gitignore` используются как дополнительные имена для исключения.

Комментарии и пустые строки игнорируются.

Пример:

```gitignore
secrets
uploads
tmp
generated
```

После этого соответствующие элементы не попадут в собранный контекст.

> **Важно:** текущая реализация `.gitignore` использует упрощённое сопоставление по имени файла или каталога, а не полноценный Git ignore parser.

# 🔐 Проверка потенциальных секретов

Перед добавлением содержимого файла `gptcopy` выполняет простую проверку на признаки случайно закоммиченных секретов.

Проверяются конструкции вроде:

```text
BEGIN PRIVATE KEY
BEGIN RSA PRIVATE KEY
api_key
apikey
secret_key
aws_access_key_id
ghp_
```

При обнаружении совпадения выводится предупреждение:

```text
[ПРЕДУПРЕЖДЕНИЕ] Файл может содержать секреты/ключи!
```

### Важно

Это **не полноценный security scanner**.

Утилита только предупреждает о потенциально опасных строках и не блокирует копирование файла.

Перед отправкой контекста в стороннюю LLM всегда проверяйте содержимое самостоятельно.

---

# 📄 Определение бинарных файлов

`gptcopy` не пытается читать бинарные файлы как обычный текст.

Для предварительной проверки используется первые 512 байт файла. Если в этом фрагменте обнаруживается нулевой байт, файл считается бинарным и пропускается.

Пустые файлы считаются текстовыми.

Это позволяет работать с проектами, содержащими изображения, архивы, бинарники и другие нетекстовые данные, не включая их содержимое в контекст.

# 📋 Буфер обмена

После формирования контекста утилита автоматически ищет доступный способ копирования.

Порядок проверки:

```text
kitten
  ↓
wl-copy
  ↓
xclip
```

---

## Kitty

Если:

```text
TERM=xterm-kitty
```

и доступна команда:

```bash
kitten
```

используется:

```bash
kitten clipboard
```

---

## Wayland

При наличии:

```bash
wl-copy
```

используется системный Wayland clipboard.

В большинстве Linux-дистрибутивов команда предоставляется пакетом `wl-clipboard`.

---

## X11

При наличии:

```bash
xclip
```

используется X11 clipboard:

```bash
xclip -selection clipboard
```

---

## 💻 Работа без clipboard-утилиты

Если ни один поддерживаемый способ копирования не найден, `gptcopy` не завершается с ошибкой.

Вместо этого готовый контекст выводится непосредственно в терминал.

То есть даже без `wl-copy`, `xclip` или `kitten` утилита остаётся рабочей.

# 📊 Статистика

После завершения `gptcopy` выводит статистику:

```text
:: Готово! Обработано файлов: 24 | Размер: 182.4 KB | ~Tokens: 46694
```

Показываются:

- количество обработанных файлов;
- размер сформированного контекста;
- приблизительное количество токенов.

Оценка токенов рассчитывается приблизительно:

```text
tokens ≈ bytes / 4
```

Это не соответствует точному tokenizer конкретной LLM.

# 🧠 Формат обычного контекста

Без `--xml` структура результата выглядит примерно так:

```text
=== PROJECT STRUCTURE ===

project/
├── src
│   ├── main.rs
│   └── lib.rs
├── Cargo.toml
└── README.md

=== SOURCE CODE ===

FILE: src/main.rs
```

Содержимое файла

```text
```

Следующий файл:

```text
FILE: Cargo.toml
```

Содержимое файла

```text
```

Таким образом, LLM получает одновременно:

1. структуру проекта;
2. список файлов;
3. содержимое каждого текстового файла.

# 📦 Архитектура

CLI построен вокруг `clap`.

Основные компоненты текущей реализации:

| Компонент | Назначение |
|---|---|
| `Cli` | Описание аргументов и параметров CLI |
| `Commands` | Описание подкоманд, включая `completions` |
| `IGNORE_LIST` | Встроенный список исключений |
| `SECRET_PATTERNS` | Шаблоны поиска потенциальных секретов |
| `is_ignored()` | Проверка элемента на исключение |
| `load_gitignore()` | Загрузка локального `.gitignore` |
| `is_text_file()` | Определение текстового файла |
| `matches_extension()` | Проверка фильтра расширений |
| `collect_files()` | Рекурсивный сбор файлов |
| `print_tree()` | Формирование дерева проекта |
| `scan_for_secrets()` | Поиск потенциальных секретов |
| `get_clipboard_process()` | Определение clipboard backend |
| `expand_tilde()` | Разворачивание `~` в домашний каталог |
| `print_completions()` | Генерация shell completion через `clap_complete` |

# 🔒 Безопасность

`gptcopy` предназначен для подготовки контекста, а не для хранения или защиты секретов.

Учитывайте несколько моментов:

- содержимое файлов читается локально;
- потенциальные секреты только обнаруживаются и помечаются предупреждением;
- результат может содержать чувствительные данные;
- после копирования содержимое находится в системном буфере обмена;
- перед отправкой контекста в LLM необходимо проверить результат.

Не используйте `gptcopy` без проверки на проектах, содержащих:

```text
.env
credentials
private keys
API tokens
SSH keys
production configuration
```

Особенно внимательно проверяйте результат перед передачей его внешней LLM.

```text
  completions  Generate shell completion script

Options:
  -c, --changed
  -m, --minify
  -x, --xml
  -e, --ext <EXT>
  -h, --help
  -V, --version
```

Точный текст справки может отличаться в зависимости от версии `clap` и версии самого `gptcopy`.

# 📌 Быстрая шпаргалка

```bash
# Весь проект
gptcopy .

# Конкретная папка
gptcopy src/

# Несколько путей
gptcopy src/ tests/

# Только изменения
gptcopy -c

# Только изменения + минификация
gptcopy -c -m

# XML
gptcopy -x

# Только Rust и TOML
gptcopy . -e rs,toml

# Git + XML + минификация
gptcopy -c -m -x

# Генерация Bash completion
gptcopy completions bash

# Генерация Zsh completion
gptcopy completions zsh

# Генерация Fish completion
gptcopy completions fish
```
